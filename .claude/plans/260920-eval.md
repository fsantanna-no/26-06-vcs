# Experiment matrix

- superseded (26/10/11) by hubs-59 in `2606-sims/p2p/p2p.lua`;
  see the Section 4 outline
- archives (5): chat, usenet, se (2 sites), wiki, github
- peers P: 1 (baseline), 5, 15
- topology: complete (1 hop), ring (P/2 hops), line (P-1 hops)

# Driver changes (2606-sims)

- superseded (26/10/11): done differently in `p2p/p2p.lua`
  (59 peers, waves of parallel pulls, local paths)
- P roots under `BASE/roots/<i>`, shared keys dir
- env: `PEERS`, `TOPO`, `K`, `STICKY`
- start: peer 0 inits, peers 1..P-1 clone from it
- post at peer `f(author)` or random
- sync neighbors per topology every K events
- daemons per peer (as `guide.sh`) or git local paths

# Metrics

- per window, per peer:
    - tips (fork count) from `list dag`
    - actions reordered vs the previous `list order`
    - `voided` lines from sync output
    - `hard fork` errors
    - post avg, sync avg, packed size
- at the end: quiesce (sync until no change), then compare
  `list order` across peers; must be byte-identical

# 4.2 Usenet, local-first (26/10/11)

- corpus: comp.compilers, archive.org usenet-comp; `yyy.mbox`
  33,814 msgs, 1988-2013, ~3 kB each, 12.5k senders
    - 71% of Date lines parse; 10,077 date-only records (1995-2000)
      spread evenly over the day; moderator batches (gaps < 10 min,
      12,588 msgs) spread over the gap before (`use-events.py`)
    - gaps p10/median/p90/mean: 20 s / 42 min / 21.7 h / 9.0 h
    - mapping: open chain, one post per message, one key per author,
      no likes/begs/dictators; gated usenet never run
- network (sims `260924-topology.md`):
    - asymmetric hubs-59: 5 S (ring + 2 chords), 9 M (fans
      15/8/6/5/4/3/2/1/1; 3/2/1 supers), 45 L (12 single-, 33
      dual-homed); 70 primary + 42 backup links; diameter 6
      (primary only; 5 with backups)
    - push with relay delay U(1, 60) s; pending timer kept
    - local-first sessions: SS always on, SM 6 h, LM 24 h, phases
      on whole hours (`SLOT=3600`); leaves post anytime, pulls
      deferred to sessions (UUCP-like)
- runs so far (5k prefix, 1987-07 to 1993-06):
    - always-on r160: 0 forks, post 0.08 s, pull 0.42 s, 19 MB
    - lf-slot (26/10/11, HEADLINE): all 59 peers identical order
      (58 vs reference), reps ok; forks 91% (58% at 500 -> 90%
      at 4k), 6,492 merges;
      visibility median 43.5 h, p90 51.7 h, max 58 h; pulls 112k
      (vs 290k always-on), work -21%; pull avg 0.85 s, max 7 s;
      peer 24 MB; sweep 55 s
    - backs blowup fixed (261010-backs): pull 115 s -> 2.75 s
- claims -> metrics for the subsection:
    - 3.6 consensus: identical `list order` at quiesce (done);
      forks per window; actions reordered per merge; tie-breaks
    - 3.7 chain time: clamps (P_i > declared time) under 1-2 day
      visibility; max clamp
    - 3.8 hard forks: partition runs: cut M01/M05/M09 for 1 day
      (< 7 d) and 8 days (> 7 d); hard forks, voided actions, reps
      changes at merge; two neighbouring supers down
    - churn (decided, not implemented): staleness of returning
      leaves, catch-up cost, forks from reconnects, load on mids
    - cost: pull time vs suffix size, bytes per sync, storage per
      peer, sweep time
- old paper (tpd-21) to contrast, not reuse: 10k msgs = 9 years,
  N=15/M=5 random syncs, forks 14%, 30 -> 42 MB, sort 100 s /
