# Claims to measure (paper -> metric)

  `list order` (empirical SEC)

# Experiment matrix

- archives (5): chat, usenet, se (2 sites), wiki, github
- peers P: 1 (baseline), 5, 15
- topology: complete (1 hop), ring (P/2 hops), line (P-1 hops)
- author to peer: sticky (hash of author) or random
    - sticky is the interesting case: branches align with member
      groups, which is what the reputation rule compares
- sync every K events: K = 10, 100, 1000

# Phases

- A: usenet 10k prefix, full matrix (cheapest driver, flat latency)
- B: all five archives at one config (P=5, ring, sticky, K=100),
  10k prefix
- C: full-length runs at the chosen config, one or two archives

# Driver changes (2606-sims)

- P roots under `BASE/roots/<i>`, shared keys dir
- env: `PEERS`, `TOPO`, `K`, `STICKY`
- start: peer 0 inits, peers 1..P-1 clone from it
- post at peer `f(author)` or random
- sync neighbors per topology every K events
- daemons per peer (as `guide.sh`) or git local paths

# Metrics

- per window, per peer:
    - tips (fork count) from `list dag`
    - actions reordered vs the previous `list order`
    - `voided` lines from sync output
    - `hard fork` errors
    - post avg, sync avg, packed size
- at the end: quiesce (sync until no change), then compare
  `list order` across peers; must be byte-identical
