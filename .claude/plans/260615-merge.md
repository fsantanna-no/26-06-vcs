## Context

Three venue versions of the same Freechains paper live under
`old/` in this project (`/x/papers/26-06-vcs/`):

| repo      | last change | main tex                       | role        |
|-----------|-------------|--------------------------------|-------------|
| tpd-21    | 2022-06     | `tpd-21.tex` (2000 ln)         | BASIS       |
| sbrc-23   | 2022-12     | `freechains/freechains.tex`    | condensation|
| sbseg-23  | 2023-09     | `freechains/freechains.tex`    | NEWEST       |

Goal: keep `tpd-21` as the basis (it is the most complete: journal
length, has the CRDT section and full Related Work), merge in the
newest prose refinements from `sbrc-23`/`sbseg-23`, AND modernize the
result to the current shipped protocol (freechains.vcs v0.20).

Scope DECIDED (2026-08): **modernize to v0.20** (not a faithful
historical merge). Reconcile the paper prose/examples to the shipped
design per `doc/{cli,guide,reps}.md`. See "Design reconciliation".

The three are SEPARATE git repos with NO shared history, so this is
a manual prose/section-level merge, not a `git merge`. Diffs are
done by section, comparing text not commits.

## Design reconciliation vs v0.20 (MODERNIZE)

Docs `doc/{cli,guide,reps}.md` @ `Freechains/freechains.vcs@main`
(binary v0.20.0) are DESIGN, not just CLI. Checked paper vs docs:

- ALREADY matches (no change): hard-fork settling window
  "7 days or 100 posts" + frozen prefix is in both papers
  (main.tex L770, sbseg L478); consensus favors higher-reps branch.

Modernization work items (paper describes OLDER model here):

- M1 Content Removal: paper says "a dislike revokes content when
  crossing a threshold" (main.tex L603, L979-1025 state machine).
  v0.20 has an EXPLICIT `revoke`/`unrevoke` vote (distinct from
  dislike), free self-revoke ("right to be forgotten"), payloads
  stored OUTSIDE the DAG and erasable via `sweep`.
  -> rewrite Content Removal to the revoke model.
  (src: guide.md #Moderation, reps.md Rule 3.b)
- M2 Reps constants: refresh concrete numbers in the rules
  narrative + tables to bootstrap 50000, reward 1000 (after 24h,
  <=1/day), cost 500 (<=12h refund), 10% transfer tax, 50000 cap,
  128 KB post cap. (src: reps.md Rules 1-4)
  Surveyed 2026-08-24 against `/x/x/freechains/vcs/doc/reps.md`
  and `doc/rules.png`; concrete old -> new mapping:

  | rule | paper (old)                  | v0.20                    |
  |------|------------------------------|--------------------------|
  | 1.a  | 30 reps bootstrap            | 50000 reps               |
  | 1.b  | +1 rep after 24h             | +1000 reps, <=1/day      |
  | 2    | -1 rep, <=12h                | -500 reps, 0-12h         |
  | 3.a  | like transfers 1 rep         | n reps, half to author, 10% tax |
  | 3.b  | revoke at >=3 dislikes       | revoke/unrevoke votes, >=1000 reps, free self-revoke |
  | 4.a  | >=1 rep to post              | afford full cost: 500 post, n vote; begging posts |
  | 4.b  | cap 30 reps                  | cap 50000 reps           |
  | 4.c  | 128kB                        | 128 KB (unchanged)       |

  Affected: `main.tex` rules-table caption (~L785) and the

  BLOCKER: `imgs/forum.png` hard-codes 30/29/1 reps in the DAG
  example -> must be regenerated, or the narrative reworded to
  avoid the figure's numbers.
  OVERLAP: rule 3.a/3.b changes are the revoke model, so do them
  together with M1, not in M2 alone.
- M3 \FC command walkthrough (main.tex L313-564) uses OLD CLI
  (`freechains-daemon start`, `keys shared`, `$family join/post`,

  `chains add init --pioneer` / `clone`, `post inline --sign`,
