## New design (v0.20)

- Git backend
    - chains are Git repositories: actions as commits, payloads as
      blobs, identifiers as hashes; content addressing, integrity,
      signing, replication "for free"
    - custom Git hooks validate commits against the reputation rules
    - sync backed by `git daemon/push/fetch` (`chain sync recv|send`)
    - ties into the CvRDT discussion (`260826-cvrdt.md`)
- Full application
    - self-merging Wiki on top of chains (was a dVCS sketch in tpd)
    - conflict resolution through consensus order (quasi-CRDT)
- Revoke
    - explicit `revoke`/`unrevoke` votes, reps-weighted, distinct
      from dislikes (old paper: dislike threshold)
    - free self-revoke, "right to be forgotten"
    - payload immediately unavailable; state machine
      begging/accepted/revoked (was BLOCKED/ACCEPTED/REVOKED)
- Sweep
    - `chain sweep` erases revoked payloads and compacts the chain;
      payloads live outside the DAG so metadata integrity survives
    - `chain abandon` drops local history from an action onward
      (manual hard-fork / reboot)
- Taxes
    - every transfer burns 10% (prevents reputation cycling)
    - like targets a post (half to post, half to author) or an
      author (whole amount)

## Also new vs sbseg23

- Constants: 50000 bootstrap, +1000 after 24h (<=1/day), -500 post
  cost (0-12h refund), 50000 cap, 128 KB payloads (was 30/1/1)
- Begging: outsiders post without reps, parked apart until an
  insider likes (`list begs`); replaces BLOCKED bag
- Refund semantics: each new action acknowledges and gradually
  refunds older posts; majority holder refunds instantly
- CLI/API surface: `chains add/rem`, `chain post inline|file`,
  `get metadata|payload`, `list dag|order|begs`, `reps author|post`
- Experiments re-run on v0.20 (sibling plan `260615-simul.md`)
- Terminology: "member" for chain identities; "forums" not
  "public forums"; arrangements/private chains removed
